CHEMICAL DATABASE AND THERMODYNAMIC MODELS

The chemical database is now connected to all three models. Open Preferences,
choose a Property model, select Chemical database, then search for components
A and B by name, formula or CAS number. Search returns only chemicals with the
data needed by that model. Apply physical model downloads and verifies both
records and the necessary activity parameters. Operating conditions and project
files are not sent to Supabase. They remain in local project storage.

The current flowsheet editor has two component slots. This change expands the
chemical catalog, not the number of component slots or reactor kinetics.
The existing synthetic A/B reactor and bundled sample mixtures still work.
The 2D, 3D and Split views share the same saved project and selected model.

MODELS

Ideal gas: PV=nRT, ideal partial pressures and temperature-dependent enthalpy
H(T)=Hf(298.15 K)+integral[Cp dT]. Supported public Cp correlations are NIST
Shomate, TRC, ChemSep equation 16 and polynomial Cp. Published coefficient
units are converted to SI by the importer. Shomate/polynomial integrals are
analytic; TRC/ChemSep integrals use 16-point Gauss-Legendre quadrature on
segments no wider than 25 K, split at correlation boundaries. Cp data is never
silently extrapolated. A documented zero per-species enthalpy reference is used
only where formation data is absent; these records are for nonreacting balances.
Mixers and specified-duty heaters solve PH with the same enthalpy functions.

Raoult: K_i=Psat_i/P, ideal liquid activities, bracketed phase splitting and PH
flash. The database release uses ChemSep vapor-pressure equation 101 and
heat-of-vaporization equation 106. Liquid enthalpy is gas enthalpy minus latent
heat. Where a latent-heat correlation is unavailable, the vapor-pressure
derivative provides an explicitly identified low-pressure approximation.

Modified UNIFAC 2.0: Dortmund combinatorial terms with the distinct published
2.0 directed interaction matrix, chemical Dortmund group assignments, excess
enthalpy from analytic temperature derivatives, and K_i=gamma_i*Psat_i/P.
The full source parameter set has 125 subgroups and 63 main groups. Only the
subset needed by selected chemicals is saved in a project. Missing assignments,
definitions or directed interactions are rejected; ordinary Dortmund parameters
are never substituted for the 2.0 matrix. Published parameters are CC BY-NC 4.0,
for non-commercial use only; the source notice is retained in each subset.

All models retain the flowsheet's 250–800 K bounds and their narrower source
ranges. Liquid models support 1–200 kPa and temperatures below critical points.
Enabling vapor-pressure extrapolation does not bypass Cp, latent-heat or critical
limits. No liquid-liquid stability search, electrolyte model, pressure correction
or liquid density is provided. The distillation template remains a single
equilibrium flash, not a staged column. Do not infer real reaction kinetics from
a chemical selection; the PBR remains the synthetic A/B teaching model.

STORAGE AND REPRODUCIBILITY

Private schema thermo_catalog stores immutable releases, compounds and parameter
sets. SHA-256 identifies the source manifest, records and parameter data. Public
read RPCs are security-invoker functions executable only by service_role.
The server uses the secret key; no Supabase secret is sent to the browser or
included in desktop companion packages. Tables have RLS enabled and no direct
anon/authenticated grants. The runtime server has read access, not import access.

The browser saves selected data with the project and revision history. JSON
export/import and offline recalculation preserve the selected record hashes.
New releases do not replace data in old projects. SHA-256 detects accidental
changes; it is not a digital signature authenticating arbitrary imported files.
Provenance records model version, catalog release, kernel hash and parameter
subset hash. Server and browser use the same Rust/WASM numerical kernel.

REBUILD AND IMPORT

1. Use .env.example to configure .env.local. In cloud mode, SUPABASE_URL and
   SUPABASE_SECRET_KEY enable runtime HTTPS reads. SUPABASE_DATABASE_URL is
   used only for import/migration. On IPv4 networks copy the Session pooler
   URL from Supabase Connect; do not guess its host. Download the server root
   certificate from Database Settings and set CHEMICAL_DATABASE_SSL_CA_FILE.
   Certificate and hostname verification remain enabled.
2. Create a Python virtual environment outside the repository and install
   scripts/catalog/requirements.txt. Then run:
     python scripts/catalog/build.py /tmp/chemical-catalog.json
   The builder independently downloads pinned public sources and verifies
   their hashes. It uses no private project inputs and no estimation fallback.
3. Validate without touching the database:
     npm run catalog:import -- /tmp/chemical-catalog.json --check
4. Install the additive schema and import using the configured database:
     npm run catalog:import -- /tmp/chemical-catalog.json --migrate
   Later imports can omit --migrate. Each import is atomic; repeated imports
   of the same release are idempotent. Existing published rows are immutable.
5. Restart the app after changing server credentials. Use Chemical database
   in Preferences; no credential is entered into the product UI.
For local development, the migration expects the standard Supabase roles
(anon, authenticated and service_role), as provided by the local Supabase stack.

VALIDATION

tests/catalog.test.ts checks 40 independent gas states, 27 binary liquid states
with each liquid model, Cp/PH consistency, heater/mixer energy conservation,
project serialization, integrity checks and missing-data rejection. Reference
values come from chemicals 1.5.2 and thermo 0.6.1, not the application solver.
Regenerate fixtures with scripts/catalog/reference.py using the built catalog.
tests/e2e/catalog.spec.ts covers selection, export, offline reload, server parity,
service errors and the preserved 3D view. Run against the actual catalog with:
  CATALOG_LIVE_TESTS=1 npx playwright test tests/e2e/catalog.spec.ts
Without that flag, UI tests use pinned public fixtures and the live test skips.
