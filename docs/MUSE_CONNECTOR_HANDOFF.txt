Project CAD Assistant 0.1.13: macOS and Linux build handoff

Source: https://github.com/dobralaszloedgar/project_cad/tree/v0.1.13
Windows release: https://github.com/dobralaszloedgar/project_cad/releases/tag/v0.1.13

This release fixes Muse builds stopping after 30 project tool calls. It removes
the shared connector's per-run call cap and ten-minute wall-clock cutoff. The
user's Stop action, disconnected-project lease and individual tool deadlines
remain active. Failed or completed runs release outstanding calls so they cannot
leave stale commands in the browser. The old Claude-specific turn cap is also
removed; the distributed companion uses Muse Code.

Muse reads the current guide and project concurrently at startup. Wonder and
Spark receive explicit guidance to request independent reads together, combine
chemical IDs in one selection, and submit coherent plans of up to 100 actions.
The website executes up to four reads concurrently while continuing its state
polls. Project edits remain sequential. Failed result delivery retries the saved
reply without replaying the edit. Existing catalogRef and revision validation
remain intact. Models decide whether to request multiple tools in a response;
the connector now executes independent requests concurrently when they do.

The supplied macOS and Linux 0.1.13 universal installers have now been verified
and added to the existing Windows release. Their bundled connector code matches
this source, and their x64/ARM64 runtimes match the pinned official Node builds.
Linux x64 installation, running upgrade, restart, uninstall integration and data
preservation passed in a Debian container. Native macOS and ARM64 execution were
not exercised during publication. No live Wonder or Spark inference was used.

The current download matrix and checksums are downloads-all-platforms.json and
SHA256SUMS-all-platforms.txt in the v0.1.13 release. These supplemental assets
preserve the original Windows-only metadata and all existing release binaries.

ACTIVATION AND VERIFICATION

Installed connectors must be rebuilt and updated: a website-only deployment
cannot remove a limit compiled into an older companion. Source users can restart
npm run assistant. Deploy/reload the website as well to enable browser batching
and independent polling. Keep the project tab connected during a build.

Regression coverage verifies 65 calls in one Muse run (sequential and parallel),
a connected run lasting twelve simulated minutes, Stop, individual tool expiry,
failed-run cleanup, parallel reads, ordered edits and retry deduplication. The
browser regression performs more than 40 calls, holds three catalog searches
open concurrently, confirms polling continues, then applies and saves once.
The 32 focused unit tests and three targeted browser checks passed on Windows,
as did TypeScript, targeted lint, formatting, generated-guide verification and
the production website build. Native Windows x64 package checks passed for the
launcher, install, update of a running companion, restart, shutdown and settings/
history preservation. The interactive NSIS wizard and ARM64 hardware were not
tested. Archive integrity and CPU architecture are checked separately.

PREPARE A CLEAN BUILD CHECKOUT

Use a fresh clone or worktree so downloads.json contains only the platforms you
actually build. Do not copy old binaries into the new version's inventory.

  git clone https://github.com/dobralaszloedgar/project_cad.git project-cad-0.1.13
  cd project-cad-0.1.13
  git checkout v0.1.13
  npm ci
  npm run typecheck
  npx vitest run tests/assistant-muse.test.ts tests/assistant-muse-tools.test.ts tests/assistant.test.ts tests/assistant-tool-queue.test.ts
  npm run docs:ai-guide:check
  npx playwright install chromium
  npx playwright test tests/e2e/assistant.spec.ts --grep "Muse builds past|auto applies by default|stale proposals cannot apply"

Use Node.js 24 or newer for the build. Packaging downloads the pinned private
Node runtimes from scripts/assistant/releases.json and verifies their checksums.

The normal release-reference policy must be available outside the repository at
~/.config/project-cad/release-policy.json, or through RELEASE_REFERENCE_POLICY_FILE.
Use your existing approved policy; do not disable the checks or commit its private
contents. See docs/RELEASE_CHECKS.txt. npm run assistant:check-source checks it.

MACOS (BUILD ON A MAC)

Requirements: Xcode command-line tools (xcode-select -p), Node/npm, and the
standard macOS packaging tools. 7zz is also needed for archive policy checks.

  npm run assistant:package
  npm run assistant:verify

Outputs in dist/assistant:
  Project CAD Assistant.app
  ProjectCAD-Assistant-macos-universal.pkg
  ProjectCAD-Assistant-macos-universal.zip
  downloads.json and per-artifact .sha256 files

The universal package contains Apple silicon and Intel runtimes. The local build
is ad-hoc signed, not notarized. assistant:verify checks the native launcher,
package, installation and update lifecycle in temporary locations. It does not
make model inference calls. Read docs/ASSISTANT_RELEASES.md before optional
signing/notarization.

LINUX (BUILD LATER ON LINUX OR A MAC)

Requirements: Node/npm, Go, GNU tar, gzip; 7zz for package checks. The installed
desktop app needs glibc 2.28+, xdg-open and a terminal emulator. No sudo for app
installation. Alpine/musl is not supported by the pinned Node runtime.

  npm run assistant:package-linux
  npm run assistant:verify-portable

Outputs in dist/assistant include x64 and ARM64 .run installers and .tar.gz
archives, ProjectCAD-Assistant-linux-universal.run, downloads.json and checksums.
Archive/hash/CPU verification is not a native runtime test. On a Linux desktop,
install the matching package as your normal user, open the app, connect a test
project, and check save/reload. Run a model prompt only when you choose to spend
credits. On macOS, the Linux .run and archive permissions can still be verified.

PUBLICATION AFTER BUILDING

The original Windows v0.1.13 assets and checksum manifest describe a Windows-only
release. Do not overwrite them or silently relabel older binaries as 0.1.13.
The supplied macOS/Linux installers contain version 0.1.13 and matching source;
they were added under previously unused asset names, with supplemental metadata.
The website manifest selects that metadata through release.manifestFilename and
release.checksumsFilename. Future changed binaries require a new release version
and commit. Preserve unchanged platforms with their actual release versions.
Publishing source/assets and deploying the website download manifest are separate
steps. Read docs/ASSISTANT_RELEASES.md and docs/RELEASE_CHECKS.txt for the
selected publisher.

The website shared-guide and parallel execution changes take effect after a
website deployment. The desktop update independently removes the call/time caps
and supplies Muse batching guidance to older compatible websites, but those
websites continue executing browser tools sequentially until they are updated.

SMALL PROCESS TO CHECK MANUALLY

Create a NEW empty project, select Muse and Auto apply, then paste:

  Build a methanol/water heating and splitting demo. Use catalog methanol
  (67-56-1) and water (7732-18-5), with Raoult's law. Feed: 10 mol/s, methanol
  mole fraction 0.40 and water 0.60, 298.15 K, 101325 Pa. Connect Feed -> Heater
  -> Splitter -> two Products. Set heater outlet to 323.15 K at 101325 Pa and
  split the outlet 60/40. Apply each coherent batch as you build. Use catalogRef
  for the verified chemical data. Simulate the saved final project and report
  product flows, heater duty, convergence and balance residuals. These are
  specified demo conditions; no kinetics or web research is needed.

The current local and hosted solvers both converged for this specification:
product flows 6 and 4 mol/s, heater duty about 21.788 kW, and zero reported mass
and energy residuals. The splitter preserves composition; it does not purify
methanol. Raoult's law is an ideal-mixture, low-pressure demonstration model.
Actual Wonder/Spark latency and adherence remain for your manual check.

Check that components and equipment appear before the final answer, edits survive
reload, and the tool trace has applied:true for each saved batch. In Review mode,
changes should await the user's Apply action; Read-only must not apply edits.
An existing project with a previously damaged snapshot needs a fresh component
selection through catalogRef. This release does not rewrite saved projects.
